### BUG-016: Límite de imagen 5 MB — se requiere 20 MiB (logo, portada, producto)

> **Proyecto:** laborregamarket  
> **Fecha reportado:** 2026-08-31  
> **Reportado por:** Agente QA / Tester Senior (requisito stakeholder: instalación local, fotos de alta calidad)

**Módulo / Componente:** Backend `MAX_IMAGE_BYTES` + Frontend `MediaUpload` / copy dropzone  
**Severidad:** Major  
**Prioridad:** P2 - Alta (histórica; no P0 de merge)  
**Caso de prueba relacionado:** `TC-MED-008`, `TC-MED-009`, `HP-MED-02` · `US-MEDIA-03` (AC F2 = 5 MB, a actualizar por CO)  
**Estado:** **Diferido** (12/09/2026) — no Verificado. BE disco **aceptado** (`TC-MED-008` Pass). Resto → [DT-F10-002](../deuda-tecnica/DT-F10-002-media-20mib-fe-bodysize.md).

---

## Inputs Utilizados

- **Stakeholder:** instalación local; adjuntar JPEG/PNG/WebP de gran calidad **≥ 20 MB**; aplica a **logo (perfil)**, **portada** y **imagen de producto** (local y catálogo admin GLOBAL).
- **Código:** `C:\Users\PC GAMER\LaBorregaMarket`
- **Contrato vigente:** `API-MEDIA-02` / `US-MEDIA-03` — max **5_242_880** bytes (el sistema **cumple** el AC F2; este ticket es **cambio de NFR**).
- **CO F10 media disco:** `CO-F10-002` (no cambia el tope de tamaño).

---

#### Descripción:

El dropzone y el API rechazan archivos **> 5 MiB** con `El archivo supera el límite de 5MB`. En despliegue local se necesitan fotos de alta calidad de **hasta 20 MiB** (`20 * 1024 * 1024` = `20_971_520` bytes).

El tope está **duplicado**:

| Capa | Constante | Efecto si no se cambia |
|------|-----------|------------------------|
| FE | `MediaUpload` `MAX_BYTES = 5 * 1024 * 1024` | Error inline; no hay POST |
| BE | `local-disk.ts` `MAX_IMAGE_BYTES = 5_242_880` | POST 400 |

**No es quick fix solo Frontend.** Hay que mover FE y BE al **mismo** número. PM debe registrar CO (`US-MEDIA-03`, contrato, copy UX); el código **no espera** el CO (stakeholder ya autorizó 20 MiB).

**No Blocker de release localhost:** media ≤ 5 MB y API 6 MiB (`TC-MED-008`) funcionan. Copy FE 5 MB y POST >20 MiB → 500 no impiden el flujo diario. [BUG-015](./BUG-015.md) está **Diferido** (DT-F10-001).

---

#### Pasos para Reproducir:

1. Sesión PROVIDER → `/proveedor` → sección «Imagen del negocio».
2. Adjuntar JPEG/PNG/WebP de **6–20 MB** como **Logo** (perfil).
3. Repetir con **Portada**.
4. «Agregar producto» → dropzone de imagen con archivo 6–20 MB.
5. (Admin) `/admin` → Catálogos → Productos → Nuevo → dropzone imagen 6–20 MB.
6. API: `POST /api/provider/media` multipart `file` + `field=logo|cover` con buffer JPEG de 6 MiB.

---

#### Resultado Obtenido:

- UI: `El archivo supera el límite de 5MB`; hint «máx 5MB».
- API: **400** mismo mensaje.
- Archivos 6–20 MB no se persisten en `UPLOADS_DIR`.

---

#### Resultado Esperado:

- JPEG/PNG/WebP **≤ 20_971_520** bytes → **200**; URL `/api/media/…`; preview en panel, Explorar y `/fruteria/[id]`.
- **> 20_971_520** → **400** / inline `El archivo supera el límite de 20MB`.
- Copy dropzone: `JPEG, PNG o WebP · máx 20MB` (logo, portada, producto local, admin GLOBAL).
- MIME y rate limit (20 uploads / 10 min) **sin cambio**.

---

#### Evidencia / Logs:

```ts
// src/lib/storage/local-disk.ts
export const MAX_IMAGE_BYTES = 5_242_880;

// src/lib/services/media.service.ts ~L51
throw new MediaValidationError("file", "El archivo supera el límite de 5MB");

// src/components/ui/MediaUpload.tsx
const MAX_BYTES = 5 * 1024 * 1024;
```

Copy UI: `ProveedorPageClient.tsx`, `ProductImageDropzone.tsx`, `AdminProductForm.tsx` — «máx 5MB».

`cloudinary.ts` conserva el mismo 5 MiB (ruta F2); alinear para no dejar un tope oculto.

`next.config.ts` no declara `bodySizeLimit`; Next puede recortar multipart **antes** del service.

---

#### Workaround (si aplica):

Comprimir/redimensionar a ≤ 5 MB. Inaceptable para el NFR local de alta calidad.
