### 🐞 BUG-014: CompactAddressBar — fila horizontal compacta (buscar + favoritas + guardar) (`/explorar`)

#### Descripción:

En `/explorar`, la banda de **captura de domicilio del paciente** (`CompactAddressBar`) ocupa demasiada **altura vertical**. Los tres controles principales — **buscar dirección**, **selector de domicilios favoritos** y **botón guardar domicilio** — deben compartir **una sola fila lateral** en tablet y desktop para maximizar el viewport del mapa y de las cards de fruterías.

**Estado actual en código** (`LaBorregaMarket`):

- `CompactAddressBar.tsx`: sección con `py-4`, `space-y-3` y contenedor `flex flex-col gap-3 lg:flex-row lg:items-end`. En viewports **&lt; lg (1024px)** la barra de búsqueda y el bloque de favoritas **se apilan verticalmente**.
- `FavoriteAddressSelect.tsx`: label visible «Favoritas» (`mb-1 block`) encima del `<select id="favorite-address">`, más botón «Guardar dirección» en `flex-wrap` — añade ~20px extra de altura.
- Altura aproximada del chrome de controles: **~100–130px** en tablet (640–1023px) por stack + label + padding.

**Brecha vs wireframe F5/F7:** `WF-explorar-mapa-primero` define en desktop una sola fila:

```text
[🔍 Dirección]  Favoritas [ Casa ▾ ] [ + Guardar ]
```

El código solo alinea en fila desde `lg:` y mantiene label apilado, por lo que **no aprovecha el ancho horizontal** en tablet.

**Alcance acordado:** layout horizontal compacto **desde ≥640px** (breakpoint `sm`/`md`); en móvil **&lt;640px** se permite stack parcial si no cabe en una fila.

**Objetivo de producto:** reducir la huella vertical de la banda de domicilio sin cambiar comportamiento funcional ni API.

---

#### Pasos para Reproducir (estado actual — mejora no implementada):

1. Abrir `http://localhost:8080/explorar?lat=25.6714&lng=-100.3089&radiusKm=10` en tablet (768×1024) o desktop (1280×800).
2. Localizar `CompactAddressBar` bajo el FilterBar (dentro de `.explore-main-scroll`).
3. Observar que el input «Buscar dirección» + botón lupa ocupan **la primera fila**.
4. Debajo, el label «Favoritas», el `<select>` y el botón «Guardar dirección» ocupan **una segunda fila** (o más si `flex-wrap`).
5. Medir altura del bloque de controles (sin contar copy «N fruterías a R km»): típicamente **&gt; 80px**.

---

#### Resultado Obtenido:

- Búsqueda de dirección, favoritas y guardar **no comparten una sola fila** en tablet (640–1023px).
- Label «Favoritas» visible encima del select incrementa altura innecesaria en tablet+.
- Padding generoso (`py-4`, `space-y-3`, `gap-3`) agranda la banda vertical.
- El mapa pierde viewport útil respecto al wireframe F5/F7.

---

#### Resultado Esperado:

| Criterio | Detalle |
|----------|---------|
| Fila única ≥640px | Input `#geocode-query` + botón lupa + `<select id="favorite-address">` + botón «Guardar dirección» en **una sola fila** (`flex-row`, `items-center`, altura uniforme `h-11`) |
| Label Favoritas | `sr-only` o `aria-label="Domicilios favoritos"` en el select; **sin** label block encima en viewport ≥640px |
| Proporciones | Input `flex-1 min-w-0`; select ancho fijo ~160–200px (`shrink-0`); botón guardar `shrink-0` |
| Padding sección | Reducir banda: `py-2 sm:py-3` (mantener `border-b border-gray-100`) |
| Móvil &lt;640px | Stack permitido: buscar arriba; favoritas + guardar en subfila inferior si no cabe en una fila |
| Meta / copy | `ExploreCount`, «Centro: …», avisos geo/error **debajo** de la fila de controles (segunda línea), no entre controles |
| Funcional | Sin cambio API; `HP-GEO-03` intacto (`#favorite-address`, `/login?redirect=`, prompt guardar) |
| Accesibilidad | Tab: geocode → buscar → favoritas → guardar; targets táctiles ≥44px; `role="alert"` en errores de búsqueda |
| Regresión | `EC-GEO-17`, `CO-F7-001`, `HP-GEO-09`, `HP-GEO-03` intactos |

#### Fix esperado (Frontend)

1. **`CompactAddressBar.tsx`**
   - Sustituir `flex flex-col gap-3 lg:flex-row lg:items-end` por fila horizontal desde `sm:` o `md:` (≥640px).
   - Unificar controles en un contenedor `flex flex-row items-center gap-2 sm:gap-3`.
   - Reducir padding: `py-2 sm:py-3` en la `<section>`.
   - Mantener formulario de geocode + `FavoriteAddressSelect` como **hermanos en la misma fila** (no wrapper `lg:w-[280px]` que fuerce columna).

2. **`FavoriteAddressSelect.tsx`**
   - Prop opcional `inline?: boolean` o clases responsive: label `sr-only sm:sr-only` / `block sm:sr-only`.
   - Eliminar `flex-wrap items-end`; usar `flex flex-row items-center gap-2 shrink-0`.
   - Botón «Guardar dirección» alineado en la misma fila que el select (altura `h-11`).

3. **`globals.css`** (opcional)
   - Token `--explore-addressbar-controls-h: 2.75rem` (~44px) para altura uniforme de la banda de controles.

4. **Layout objetivo (referencia JSX):**

```tsx
<section className="border-b border-gray-100 bg-white px-4 py-2 sm:px-6 sm:py-3">
  <div className="flex flex-col gap-2 sm:flex-row sm:items-center sm:gap-3">
    <form className="flex min-w-0 flex-1 gap-2" onSubmit={submitSearch}>
      {/* input #geocode-query + botón lupa h-11 */}
    </form>
    <FavoriteAddressSelect inline className="shrink-0 sm:flex-row" {...props} />
  </div>
  {/* errores, geoDenied, pinLabel, ExploreCount — debajo */}
</section>
```
