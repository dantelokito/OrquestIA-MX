### 🐞 BUG-001: US-AUTH-01 documenta password mínimo 6 pero API exige 8

> **Proyecto:** laborregamarket  
> **Fecha reportado:** 2026-08-05  
> **Reportado por:** Agente QA

**Módulo / Componente:** Documentación / PM  
**Severidad:** Minor  
**Prioridad:** P3 - Media  
**Caso de prueba relacionado:** TC-AUTH-005  
**Estado:** Abierto

---

#### Descripción:

La user story `US-AUTH-01` indica en su regla de negocio que el login acepta password mínimo 6 caracteres. La implementación actual en `src/app/api/auth/login/route.ts` y el contrato `API-AUTH-01` unifican el mínimo a 8 caracteres (BL-009 resuelto en backend).

#### Pasos para Reproducir:

1. Leer `US-AUTH-01` regla de negocio.
2. Enviar POST `/api/auth/login` con password de 7 caracteres.

#### Resultado Obtenido:

400 con mensaje `"Contraseña mínima 8 caracteres"`.

#### Resultado Esperado:

Según AC desactualizado: aceptar 6+ chars. Según API-AUTH-01 actual: 8+ chars (correcto).

#### Evidencia:

```json
{
  "request": { "email": "cliente@demo.mx", "password": "Demo12!" },
  "response_error": { "error": "Contraseña mínima 8 caracteres", "status": 400 }
}
```

---

#### Verificación de fix

- [ ] Actualizar US-AUTH-01 a min 8 caracteres
- [ ] Re-prueba TC-AUTH-005
