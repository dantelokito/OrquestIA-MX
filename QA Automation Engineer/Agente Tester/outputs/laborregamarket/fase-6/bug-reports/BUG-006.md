### 🐞 BUG-006: `pdfkit` no está en package.json (US-DASH-06 / reports.pdf)

> **Proyecto:** laborregamarket  
> **Fecha reportado:** 2026-08-17  
> **Reportado por:** Agente QA / Tester Senior

**Módulo / Componente:** Backend / API PDF  
**Severidad:** Major  
**Prioridad:** P1 - Inmediata  
**Caso de prueba relacionado:** `TC-REP-008`  
**Estado:** Cerrado (17/08/2026 — `pdfkit` ^0.19.1 en `package.json`). El 500 runtime del PDF es **BUG-009**.

---

#### Descripción:

La ruta `GET /api/provider/reports.pdf` y `src/lib/reports/pdf.ts` importan `pdfkit`. El `package.json` de la app no lista `pdfkit`. El PDF Must de Fase 6 no puede ejecutarse de forma reproducible hasta instalar y fijar la dependencia.

---

#### Pasos para Reproducir:

1. Revisar `LaBorregaMarket/package.json` dependencies.
2. Abrir `src/lib/reports/pdf.ts` línea 1: `import PDFDocument from "pdfkit"`.
3. (Cuando la app esté up) `GET /api/provider/reports.pdf?grain=day&date=2020-01-01` autenticado PROVIDER.

---

#### Resultado Obtenido:

Inspección estática: módulo no declarado. Ejecución HTTP no corrida (app no escuchaba en 8080/8081 desde el runner QA).

---

#### Resultado Esperado:

`pdfkit` en lockfile; 200 `application/pdf` con bytes `%PDF` en periodo vacío.

---

#### Evidencia / Logs:

```
src/lib/reports/pdf.ts: import PDFDocument from "pdfkit"
package.json: sin pdfkit
```

---

#### Workaround (si aplica):

`npm install pdfkit` (+ types si aplica) y commitear lockfile.

- [x] Dependencia instalada (`pdfkit` + `@types/pdfkit`)
- [x] Re-prueba TC-REP-008 — **sigue Fail** por 500 (ver BUG-009, no por módulo faltante)
