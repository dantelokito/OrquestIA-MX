#### Descripción:

Al seleccionar productos en el detalle de frutería y pulsar **«Ver carrito»** (desktop) o **«Encargar»** (móvil), la app navega a `/carrito` y lanza una excepción no capturada. Next.js muestra [`global-error.tsx`](C:\Users\PC GAMER\LaBorregaMarket\src\app\global-error.tsx): título «Algo salió mal.», mensaje `crypto.randomUUID is not a function`, botón «Intentar de nuevo». El usuario **no puede ver el carrito ni confirmar el pedido**. El API `POST /api/orders` **no se llama**.

**Causa raíz:** `CartPageClient` genera la clave de idempotencia en el **inicializador de `useRef`**, que se ejecuta al montar el cliente:

```tsx
const idempotencyRef = useRef(crypto.randomUUID());
```

`crypto.randomUUID` no es función cuando:

- el origen no es contexto seguro (`http://IP` / hostname distinto de `localhost` / `127.0.0.1`);
- el navegador no implementa Web Crypto UUID.

Chromium Playwright contra `http://127.0.0.1:8080` a menudo **no** reproduce el crash (secure context). El spec `e2e/cart-uuid.spec.ts` fuerza `randomUUID = undefined` para cubrir el entorno del reporter.

**Misma deuda (un solo ticket):** `PosPageClient.tsx` L54, L154, L227.

**Backend:** no aplica. Cero contrato, cero Prisma, cero 5xx. Handoff solo Frontend.

#### Fix esperado (Frontend)

Ver [`QA-F10-handoff-frontend.md`](../QA-F10-handoff-frontend.md) y [`activation-prompt-frontend-BUG-015.txt`](../activation-prompt-frontend-BUG-015.txt).

1. Helper `newIdempotencyKey()` (p. ej. `src/lib/uuid.ts`): `randomUUID` solo si `typeof === "function"`; si no, UUID v4 con `getRandomValues` o fallback.
2. Sustituir las 4 llamadas en `CartPageClient` y `PosPageClient`.
3. Lazy-init del `useRef` (no llamar UUID en el inicializador si depende del cliente).
4. No tocar API órdenes ni copy de `global-error` (el error debe dejar de lanzarse).

Usar **Chrome/Edge + `http://127.0.0.1`** (secure context). Ese es el ambiente de release v0.10.2 (stakeholder 12/09). El crash permanece en `http://IP` LAN.
