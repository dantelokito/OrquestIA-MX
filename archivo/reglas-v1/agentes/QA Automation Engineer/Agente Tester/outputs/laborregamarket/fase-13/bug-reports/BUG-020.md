### 🐞 BUG-020: POST entradas de inventario responde 500 (schema no importado)

> **Proyecto:** laborregamarket  
> **Fecha reportado:** 2026-09-16  
> **Reportado por:** Agente QA / Tester Senior

**Módulo / Componente:** Backend / API `POST /api/provider/inventory/[providerProductId]/entries`  
**Severidad:** Blocker  
**Prioridad:** P1 - Inmediata  
**Caso de prueba relacionado:** `TC-F13-008`, `TC-F13-011`, `TC-F13-006b`  
**Estado:** Verificado  
**US:** US-DASH-12, US-INV-07 (seed onHand), API-INVENTORY-13  
**Rol responsable:** Backend

---

#### Descripción:

Toda alta de `InventoryEntry` por HTTP responde **500** `{ "error": "Error interno" }`. El servicio `addInventoryEntry` y el schema Zod `inventoryEntrySchema` existen; la ruta usa `inventoryEntrySchema.parse` **sin importar** el símbolo desde `@/lib/validators/inventory`. Eso dispara `ReferenceError` antes de validar o de aplicar `OfferArchivedError` (409).

Consecuencia: no se persisten entradas Must, el reporte sucursal no puede listar `entries` nuevas, y no se puede sembrar `onHand` para probar `confirmDiscard` (US-INV-07) vía API.

Vitest de la app (373/373) no ejercita esta ruta real (el test de archivo mockea otros handlers).

---

#### Pasos para Reproducir:

1. App `http://127.0.0.1:8080`, rama `feat/f13-archivo-oferta-unidad`, migración `20260916180000_f13_archivo_oferta_unidad` aplicada.
2. Login API `frutas@elparaiso.mx` / `Demo1234!`.
3. Crear LOCAL vía `POST /api/provider/local-products`.
4. `POST /api/provider/inventory/{providerProductId}/entries` body `{ "quantity": "1.250", "receiveAs": "CATALOG" }` con cookies de sesión.

---

#### Resultado Obtenido:

HTTP **500** `{ "error": "Error interno" }`. Sobre oferta archivada: también **500** (no 409).

---

#### Resultado Esperado:

- Oferta visible: **200** con ficha; fila en `GET /api/provider/reports/inventory` (`API-INVENTORY-13`, `API-PROVIDER-REPORTS-INV-13`).
- Oferta oculta: **409** `{ "error": "Oferta oculta", "details": [{ "field": "providerProductId", ... }] }`.
