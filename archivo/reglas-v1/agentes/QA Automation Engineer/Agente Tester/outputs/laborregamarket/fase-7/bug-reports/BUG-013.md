### 🐞 BUG-013: FilterBar colapsable al scroll hacia abajo — pestaña de re-expansión (`/explorar`)

> **Proyecto:** laborregamarket  
> **Fecha reportado:** 2026-08-23  
> **Última actualización:** 2026-08-24  
> **Reportado por:** Agente QA / Tester Senior

**Módulo / Componente:** Frontend / `FilterBar.tsx` + `ExplorePageClient.tsx`  
**Tipo:** Mejora UX (enhancement)  
**Severidad:** Major  
**Prioridad:** P2 - Alta  
**Caso de prueba relacionado:** `HP-GEO-19`, `EC-GEO-19`, `UF-GEO-01`  
**Estado:** Cerrado  
**Rol responsable:** Frontend  
**Dependencia:** [BUG-012](./BUG-012.md) cerrado (FilterBar acoplado al Header)

---

#### Descripción:

En `/explorar`, el usuario necesita **más viewport** para consultar el mapa o revisar las cards de fruterías filtradas. Se solicita que el **FilterBar** (chips Orgánico, Mayoreo, A domicilio, Verificado, Frutas, Verduras, Agrícola + botón **«Usar mi ubicación»**) pueda **ocultarse automáticamente** al hacer scroll **hacia abajo** en el contenido principal (`.explore-main-scroll`).

Al ocultarse:

- El Header permanece visible (sin cambio).
- Aparece una **pestaña ligera centrada** bajo el Header (o en el borde inferior del chrome) para **re-expandir** el FilterBar.
- Los **filtros activos se conservan** (`verified`, `category`, chips `aria-pressed`); el colapso es solo visual, no resetea query ni estado.
- Al expandir de nuevo, el FilterBar muestra las mismas opciones y el CTA geo.

**Objetivo de producto:** maximizar espacio para mapa y resultados sin perder acceso a filtros al navegar hacia abajo.

**Nota:** no es un defecto de layout como BUG-012; es una **mejora incremental** sobre el chrome fijo una vez resuelto BUG-012.

---

#### Pasos para Reproducir (estado actual — mejora no implementada):

1. Abrir `http://localhost:8080/explorar?lat=25.6714&lng=-100.3089&radiusKm=10` en desktop (1280×800).
2. Confirmar FilterBar visible bajo el Header (post fix BUG-012).
3. Activar un filtro (ej. chip **Verificado**).
4. Hacer scroll hacia abajo ≥ 120px en `.explore-main-scroll`.
5. Observar que el FilterBar **no** se colapsa y no aparece pestaña de re-expansión.

---

#### Resultado Obtenido:

- FilterBar ocupa altura fija permanente (~72px + padding) aunque el usuario ya está explorando mapa o cards.
- No hay affordance para recuperar filtros sin volver al tope del scroll.
- Viewport útil del mapa y de la lista se reduce.

---

#### Resultado Esperado:

| Comportamiento | Criterio |
|----------------|----------|
| Colapso | Scroll **hacia abajo** en `.explore-main-scroll` supera umbral (sugerido ≥ 80–120px) → FilterBar se oculta con transición suave (`prefers-reduced-motion`: instantáneo o sin animación) |
| Pestaña | Queda visible una **pestaña central mínima** (≈ 24–32px alto, ancho ~48–64px) con icono chevron ▼/▲ o «Filtros»; `min-h` táctil ≥ 44px en móvil |
| Re-expansión | Tap/click en pestaña **o** scroll hacia arriba cerca del tope → FilterBar vuelve a mostrarse completo |
| Estado filtros | Filtros activos persisten; URL (`verified`, `category`) sin cambio al colapsar/expandir |
| Indicador | Si hay filtros activos y barra colapsada, la pestaña muestra badge o contador (ej. «2 filtros») — recomendado |
| Accesibilidad | Pestaña: `role="button"`, `aria-expanded`, `aria-label="Mostrar filtros"` / `aria-label="Ocultar filtros"`; teclado Enter/Space |
| Regresión | `EC-GEO-17`, `EC-GEO-18`, `CO-F7-001`, `HP-GEO-09` intactos |

**Fuera de alcance de esta mejora:** colapsar el Header; ocultar CompactAddressBar; cambiar API.

---

#### Evidencia / Referencia:

Solicitud de producto (captura F7): zona Header + FilterBar debe ser chrome; al explorar mapa/cards el usuario pide **colapsar filtros** para ganar espacio, con pestaña central para restaurarlos.

Wireframe base: [WF-explorar-mapa-primero](../../../../../Agente UX UI/Agente UX UI/outputs/laborregamarket/fase-7/wireframes/WF-explorar-mapa-primero.md) — FilterBar en banner; delta F7 pendiente de wire UX para estado colapsado.

---

#### Fix esperado (Frontend)

1. **Prerrequisito:** layout BUG-012 (`FilterBar` fuera de `.explore-main-scroll`, chrome fijo).
2. Nuevo estado `filterBarCollapsed` en `ExplorePageClient` (o hook `useFilterBarCollapse`), escuchando `scroll` de `.explore-main-scroll`:
   - `scrollTop` aumenta y supera umbral → colapsar.
   - `scrollTop` disminuye hacia 0 **o** click en pestaña → expandir.
3. `FilterBar`: variante colapsada (altura 0 / `translate-y` / `max-h-0 overflow-hidden`) + componente `FilterBarExpandTab` centrado bajo Header.
4. Tokens CSS sugeridos en `globals.css`: `--explore-filterbar-h`, `--explore-filter-tab-h`, transición 200ms.
5. No desmontar chips al colapsar (preservar estado React y `aria-pressed`).

Ver handoff: [`QA-F7-handoff-frontend.md`](../QA-F7-handoff-frontend.md)

---

#### Workaround (si aplica):

Ninguno. El usuario debe convivir con el chrome fijo de filtros hasta implementar la mejora.
